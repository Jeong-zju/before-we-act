# S0 四候选 4-GPU/tmux 运行手册

本手册对应路线文档 S0 的四个参考坐标：

| GPU | 分支 | 候选 |
|---:|---|---|
| 0 | `round/s0-b0-legacy-moe-ensemble` | sparse MoE legacy chunk + temporal ensemble |
| 1 | `round/s0-b1-legacy-dense-ensemble` | compute-matched dense legacy chunk + temporal ensemble |
| 2 | `round/s0-b2-flow-reference` | 现有 Rectified Flow，future head 完全旁路 |
| 3 | `round/s0-b3-legacy-moe-latest` | B0 checkpoint + latest chunk |

B3 按路线要求复用 B0 的 immutable checkpoint，避免把训练随机性混入
`temporal_ensemble` 与 `latest_chunk` 的单变量比较。因此 GPU 3 会在共享准备
完成后等待 B0 checkpoint，然后执行独立的完整 Gate20；这不是漏启动训练。

## 一键启动

远程机器只需预装至少四张可见 GPU 对应的驱动，以及 `git`、`tmux`、`jq`、
`python3` 和 `nvidia-smi`。`uv` 缺失时脚本会在工作区内自动安装固定的
`uv 0.9.26`。服务器已有且仅有一个不可退出的永久 tmux session；请直接在该
session 的任意现有 window 中，于 `feat/model-improvements` 分支执行：

```bash
git clone --branch feat/model-improvements --single-branch \
  https://github.com/Jeong-zju/fe-pc-wam.git
cd fe-pc-wam
./scripts/launch_s0_4gpu_tmux.sh --run-id s0-20260728
```

脚本会在终端显示 `Hugging Face read token (input hidden)`，此时粘贴具备
DINOv3 gated 模型读取权限的 token 并回车。输入不回显；token 不需要也不允许
通过 `export HF_TOKEN=...` 预置。它只通过权限为 `0600` 的临时 FIFO 交给
`prepare` 窗口，读取后立即删除，不出现在 tmux 命令、日志或进程参数中。

启动器会自动设置仓库、worktree、数据、artifact、uv 环境/cache、RoboFactory、
checkpoint、输出和日志路径；自动从 `origin` 获取四个候选分支，并在本地分支
缺失时建立 tracking branch。启动器会先将四个候选 refspec 幂等加入
`remote.origin.fetch`，因此上述 `--single-branch` clone 也可直接运行；无需
预先手工创建 worktree 或设置任何路径变量。

启动器不会创建或退出 tmux session，也不会执行 `tmux attach`。它自动识别当前
session；若从 tmux 外执行，则仅在系统恰好存在一个 session 时使用该 session。
对于 `--run-id s0-20260728`，它只新增以下六个 window：

```text
s0-20260728-prepare
s0-20260728-b0
s0-20260728-b1
s0-20260728-b2
s0-20260728-b3
s0-20260728-monitor
```

启动完成后，当前 tmux client 默认切换到 monitor window。所有新增 window 均
设置 `remain-on-exit=on`，失败窗口也会保留用于排查。若不希望自动切换，添加
`--no-focus-monitor`。

执行前只查看计划：

```bash
./scripts/launch_s0_4gpu_tmux.sh --run-id s0-20260728 --dry-run
```

## 共享数据集

`prepare` 窗口会首先执行冻结的 `uv sync`，优先校验 gated 访问并下载/校验
DINOv3 权重，再自动下载两个固定 revision 的数据集、RoboFactory 固定 commit
及其场景资产，避免在无 DINOv3 权限时先传输约 453 GB 数据。已经完整存在的项目
会通过 hash、architecture、sentinel 或 manifest 校验后复用，因而重启不会
重复下载。默认共享当前 `feat/model-improvements` worktree 下的：

```text
datasets/robofactory_multitask/
├── lift_barrier/
└── long_pipeline_delivery/
```

候选 worktree 只建立只读使用语义的符号链接，不复制约 453 GB 数据。若数据已经
存在于这个自动路径，脚本直接复用。DINOv3 artifact、`uv` 环境/cache 和
RoboFactory checkout 同样共享；checkpoint、训练日志、闭环 JSON 和视频则按
run/candidate 隔离，避免并发覆盖。首次下载数据前会检查至少 550 GiB 可用空间。

## 查看状态

当前永久 session 内直接选择 monitor，无需且不得重新 attach：

```bash
tmux select-window -t :s0-20260728-monitor
```

不进入 tmux，只打印一次状态：

```bash
python3 scripts/s0_runtime.py monitor \
  --once \
  --run-root outputs/s0_runs/s0-20260728
```

monitor 同时显示：

- 四张 GPU 的利用率与显存；
- B0/B1/B2 的 optimizer update、百分比和最近 loss；
- B3 等待/复用 B0 checkpoint 的状态；
- LiftBarrier 与 LongPipelineDelivery 已完成 episode/成功数；
- Gate20 是否完整落盘；
- prepare、训练、验证、完成或失败状态。

原始日志位于：

```text
outputs/s0_runs/<RUN_ID>/
├── prepare.log
├── shared_artifact_sha256.txt
├── run_manifest.json
└── candidates/{b0,b1,b2,b3}/
    ├── status.json
    ├── train/progress.jsonl
    ├── logs/candidate.log
    ├── checkpoints/
    └── validation/
```

## 中断与故障

服务器的永久 session 始终保留；不要执行 `tmux detach`、`tmux kill-session`
或重新 attach。SSH 连接变化不影响其中的进程。某个候选失败时，其 window 与
日志会保留，其他候选继续；monitor 将该候选标为 `failed`。训练器的 resume
checkpoint 保存在该候选隔离目录中，修复基础设施问题后可在原 window 使用同一
环境重新执行 `scripts/run_s0_candidate.sh`，不得删除或覆盖已经完成的正式
checkpoint。

同一个 `RUN_ID` 不允许再次由 launcher 创建，以防覆盖证据。确需全轮重跑时使用
新 ID，并保留旧 run 作为失败记录。
